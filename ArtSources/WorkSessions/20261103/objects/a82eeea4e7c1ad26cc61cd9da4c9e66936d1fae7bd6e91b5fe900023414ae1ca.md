## Runtime and concrete risks

- **Attack routing:** `Assets/Darklight/Runtime/Character/DarklightWeaponRedesignBank.cs` line 224 reads `model.Attack.displayName`; context lookup requires exact `attackKey`. Fallback mapping source lines: 236: if(page.action!="Attack"||page.attackKey!=(pass==0?key:weapon==0?"Leve1":weapon==3?"Serra de Entrada":"Direto da Ruína")||!Load(page))continue;. Archived family names require matching displayName and an applied page in the current context; see source-literal evidence table.
- **Attack phases:** 48 active attack pages omit explicit `startupFrames`/`activeFrames`; runtime count fallback maps 4-frame pages as 2/1/1 and 3-frame pages as 1/1/1. Sixteen pages have explicit phase counts. Descriptor phase-label sequences (6 unique patterns) are in JSON/CSV; they are metadata labels, not motion proof.
- **Non-looping states:** all 72 Dead/Hurt/Parry pages are non-looping; positive frame durations were found in 193/193 active pages using the catalog/descriptor data.
- **Moto idle:** provided by the separate `DualSawsPose` consumer; catalog idle absence is not a coverage defect.
- **guardContact:** metadata is present but no `Runtime` C# file references the literal; it is not wired as combat contact/collision data.
- **Particles:** `Observe` uses fixed owner-relative heights line 84: float height=kind==DarklightActionParticleKind.Dodge?.12f:kind==DarklightActionParticleKind.Death?.4f:.85f;. This is not frame/anchor-aware and does not consume guardContact.
- **Timing mismatch:** five Leve3 Katana pages store 40/40/100/180 ms in the catalog while their descriptor frames each say 120 ms. Attack playback uses attack phase timing rather than frame durations, but the records disagree and should be reconciled before treating timing as a single source of truth.
- **Naturalness/reference sync:** this audit did not inspect a rendered playback against the official Dead Cells/Hades references; metadata cannot support that claim. Unity import/runtime state remains unverified.
